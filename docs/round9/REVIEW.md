# Round 9 评审记录

本轮基于实际生产 `59f2bd1`，PR base 为性能分支（PR #15），避免与已部署的前轮功能混在同一 diff。未部署正式服务。

## 设计与实现检查

- 棋盘：桌面解除中栏上限，5×5 使用 1.75 比例，6×6 使用 1.5 比例；专注模式同时取消旧固定行高。手机允许页面及棋盘滚动，最后一行须能移到固定导航上方。既有完整棋盘首屏断言与本轮“可滚动以保证辨识度”要求冲突，已替换为真正的可达性检查。
- 侧栏：最近三条线索与完整历史独立于成员区；成员保留队伍和角色文字、在线状态、折叠及有界内滚动。战况继续使用服务端 clueRecords，连接诊断单独折叠；聊天、积分和旁观使用同一稳定页签区，未读数不参与标签宽度布局。
- 通知：猜牌、高光、成就共用一个显示位置，匹配 roomId/matchId，复用事件账本去重，待播队列优先猜牌。过期回合高光进入历史但不弹出；当前局的猜牌结果不因进入下一回合丢失。
- 封面：复用性能分支的 Cover 与 probeCover；延迟只增加占位和重试，不改原图 URL、不取消原图请求、不扩大并发。慢封面的最终恢复由既有 61 秒故障专项验证。
- 成员管理：Socket 身份来自绑定会话，不接受客户端自称房主；房间锁内复核真实在线房主、目标和阶段。任命新队长只在允许大厅执行，原队长降为队员；移出拒绝房主自踢，移出目标仅清理本房间 Socket 绑定及旧席位归属。原有随机分队、安全交接和接任保留。
- 隐私与性能：未修改候选拖拽判定、claim/protection/interference 投影、个人图谱权限、计分或成就规则。增量协商、全量恢复、头像资源引用、目录按需接口与倒计时局部更新保留。

## 回归中处理的问题

1. 手机标题被新增退出入口挤窄：工具区改为单独一行。
2. 专注模式旧 Grid 固定行高仍压扁卡牌：显式改为 auto，并同时检查宽高增长。
3. 手机和桌面旧“首屏必须放下整盘”测试：依据本轮验收标准改查可滚动到达末行，保留横向溢出与触屏操作检查。
4. 首轮并行浏览器出现页面空白/超时，且开发期间 HMR 影响拖拽定位：冻结应用代码、改为串行运行。具体最终结果以 ACCEPTANCE.md 和 test-results.json 为准，早期失败不计通过。
5. 自定义池接口原本限制一次提交 2500 个 ID：保持限制，使用 171/500 个系列池，在含额外 5000 条的 6810 作品目录中回归；不放宽生产输入限制来迁就测试。
6. 结算后嵌入的“下一局计划”没有请求内置作品池目录，删除来源池后无法换池：补齐仅房主打开配置时的按需请求，增加加载状态与失败重试。既有角色测试改为等待异步目录选项，抢夺测试等待界面保护期提示结束；服务端 10 秒边界仍由原规则单测检查。
7. 新成员接口额外拒绝揭幕猜番房间与残留锁定名单，避免跨玩法影响原有裁判和席位路径。
8. 慢图占位的重试点击拦截了棋盘原有预览：去掉阻断冒泡，卡片入口继续响应；新增原图与备用图都失败时的真实预览/确认猜牌回归。
9. 最终普通 Round 8 重跑中，本机 Node 在服务启动时发生 semi-space 内存分配失败，导致加入按钮等待超时；该次没有计入通过。保留失败日志后单独重跑，最终状态以验收表为准。
