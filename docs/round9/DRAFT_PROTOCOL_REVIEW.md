# Round 9 组牌协议提案（待确认，未启用）

本 PR 的运行代码继续使用 Round 8 的 180 秒组牌与同阶段干扰。以下为评审契约，不是已实施的新规则。

## 服务端状态机

`planning → guide → draft → interference → sealing → sealed → playing`

- planning：房主配置规则快照；建议选牌 180/240/300 秒，5×5 默认 180、6×6 默认 240；独立干扰 30/45/60 秒，建议 45。均待批准。
- guide：仅两队指定队长读取候选、私人书签和就绪。是否允许改队长待批准，本 PR 新房主管理只允许 planning，先取消预览再操作。
- draft：服务器截止时间决定阶段；保留 10 秒保护、最后 20 秒禁抢、原子替换。双方 done 或截止锁定普通 manual 集合。
- interference：普通 take/release/replace 全部拒绝；每队最多一张空闲作品。建议可替换、不可主动撤回，双方确认或截止推进；最终权限与可见字段待批准。
- sealing：在房间锁中执行一次：干扰校验 → 随机互换 → 随机补位 → 封存。仅双方普通 manual 各随机一张；排除干扰、随机补位、中立、刺客。任一队零 manual 建议跳过并记录原因，待批准。
- sealed：不可修改阵营、队长或牌组；现有安全交接独立处理；五秒开局仍需有效在线队长。

## 数据、幂等与兼容

新增可选 `draftRulesVersion: 2`、`selectionSeconds`、`interferenceSeconds`、`independentInterference`；在 planning 创建规则快照后固定于 plan。旧房间、旧存档缺省 version=1，继续原流程，升级不重置正在准备的截止时间。

新请求含 roomId、planId、planVersion、stageVersion、requestId。服务器先验证 Socket 真实席位、角色、队伍、阶段、版本，再在同一房间锁内执行。ACK 回传全部版本和 requestId；客户端忽略过期 ACK，超时重试复用 requestId。仅将去重键保存到对应计划的有界缓存；并发 done、截止定时器、重连都调用同一 compare-and-transition。

`sealedAt` 与 `swapResult`（执行版本、是否执行及跳过原因）写入同一封存结果。重复请求不得重新抽样。重启恢复必须先有可靠持久化事务；当前内存房间不能宣称可跨进程恢复。旧客户端不支持 interference 时应拒绝加入 v2 队长席并提示升级，不能把新阶段伪装成 draft。

回放增加可选 rulesVersion 与公开的交换执行摘要；旧回放按 v1 读取，不把私人来源、书签或原始 claims 放入公共回放。公开房间投影继续仅发送匿名已选集合，队长视图按现有权限过滤。截止由服务端推进，离线不得无限卡住；封存之后继续遵守现有开局席位检查。

## 权限矩阵

| 操作 | 房主 | 本队队长 | 队员 / 旁观 |
| --- | --- | --- | --- |
| planning 配置、分队、任命、移出 | 允许，服务端鉴权 | 拒绝 | 拒绝 |
| guide 就绪 | 仅兼任队长时 | 本队 | 拒绝 |
| draft 选取 / 抢夺 / 原子替换 | 仅兼任队长时 | 本队，遵守保护与截止 | 拒绝 |
| interference 投放 / 完成 | 仅兼任队长时 | 本队，具体规则待确认 | 拒绝 |
| sealing 随机互换、补位 | 服务器自动 | 拒绝 | 拒绝 |
| locked 阶段管理正式席位 | 拒绝新接口；使用既有安全交接/退出流程 | 拒绝 | 拒绝 |

## 需要产品确认

1. 180/240/300 与不同棋盘默认值；旧局维持 v1？
2. 干扰是否可关闭、默认时长、双方完成立即推进、离线等到截止？
3. 干扰可替换/撤回、保护期与对方队长可见信息？
4. 零 manual 跳过互换还是强制至少手选一张？
5. 锁定→干扰→互换→补位顺序，阶段间候选与匿名已选仍可查看？
6. guide 改队长、playing 移出正式成员是否另行开放？本 PR 采用仅 planning 管理。
7. 离线队长在截止自动推进，但 sealed 仍等待有效在线队长，是否接受？

批准后需新增：所有时长边界、双 done/定时器竞争、断线跨阶段、重复 ACK、旧版本、零 manual、重复封存、角色撤销与两队队长/普通队员/旁观投影测试。在批准之前不加入可开启新规则的产品入口。
