## 封面原因与修复

旧版等待三秒后给仍在加载的原图设置 `display:none`，会失去懒加载所需的布局条件。现在保留图片尺寸，用透明度和绝对定位占位层显示等待状态；进入可见区域后主动继续加载，原始请求可晚到成功，点击重试会重启原图请求。

备用缓存原先只有 4.5 秒的上游超时。实测服务器直连成功封面约需 6.58 秒，且用户截图中的 `mono女孩` 在发布前同源缓存请求恰好 4.50 秒返回 503，见 [发布前封面抽查](covers-before.json)。缓存上游改为 12 秒，浏览器单路备用探测为 15 秒。服务端仍限制四路冷缓存下载，浏览器备用探测仍为单路；已缓存图片直接读取。PNG 导出仍使用原来的 4.5 秒期限，URL、类型与大小校验保持生效。

生产首页已经设置 `Cache-Control: no-cache, no-store, must-revalidate`。一直打开的旧页面仍需刷新，才能执行新资源。
