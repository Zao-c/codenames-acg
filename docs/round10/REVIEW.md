# Round 10 V2 评审记录

本轮沿用正式 React 页面、品牌、玩法和服务端权限。原有设置入口与房主管理已实现，因此是在原组件中补齐行为，并未从附件 HTML 重建产品。

## 本轮修正

1. 大厅三栏由平铺信息变成玩法摘要、队伍与成员、下一步。8 人加完整管理说明会把主按钮推到首屏下方，因此将次要分队／队长工具收进可展开区域，保留席位选择和待分队拖放区，主按钮位于准备进度之后。三栏有最小高度但不裁掉成员；中屏下一步另起一行，手机纵向排列。
2. 设置表单新增草稿比较、无修改不写入、双层放弃确认和提交锁。成功必须核对同房间计划 ID、版本和持久配置；自定义作品池另读受权限保护的池快照核对。ACK 丢失先同步读状态，不自动重发；未确认保留草稿，可核对后显式重试，旧 ACK 不修改新房间。
3. 整牌蒙层使用独立覆盖层，CSS 与 Canvas 共用色值。原有 span 选择器优先级造成标题区域仍出现实色带，像素测试确实检测到上部 `[150,106,113]`、下部 `[28,32,40]`，随后修正选择器并重新通过四阵营／两主题上、下采样一致检查。没有使用逐牌 blur/backdrop-filter 或重编码图片。
4. 队长未翻归属只有预知标签与虚线边界，不加已翻蒙层；文字牌保留明显阵营背景。终局、逐回合复盘、PNG 保留真实翻牌状态，赛后未翻归属不会误标“已翻”。
5. 取消草稿会同时关闭两层弹窗，原简单滚动锁存在恢复顺序风险；改为计数锁，最后一个弹窗关闭才恢复原页面滚动。
6. 实际 SPA 切房暴露既有竞态：待发送初始配置可能在新会话确认前被旧大厅消费；并且 `leave_room` 清理没有限定绑定房间，会删掉同 Socket 的新房间绑定。增加会话／房间一致性检查，并把清理限定为请求目标房间。未改变可操作角色、阶段或跨房间权限。新增浏览器用真实服务器 ACK 延迟验证此路径。
7. 大目录只在房主打开编辑时按需读取，列表与当前池预览每页最多 60 项，社区池继续服务器搜索／分页，房间广播不加入完整目录。

## 测试适配与保留限制

- 初始原型自动化误等隐藏层“可见”、终局自动化未先展开棋盘、跨房间自动化误用链接及漏掉站点既有确认，均修正定位／流程后重跑。附件仍只是本地演示，没有当作服务端验收。
- Round 5 旧测试只等待房主进入 draft 就读取其它端，改为等所有被检查端均收到 draft，保留原来的所有隐私断言。
- 收起次要管理工具后，旧随机分队测试先实际点击展开，再检查按钮或执行分队；没有删除相关功能与权限检查。
- Round 8 旧测试要求一次渲染 171 个池条目，与本轮分页要求冲突。改为逐页检查 60／60／51 项、完整且不重复的作品名单（沿用服务端规范顺序）以及搜索，仍验证全部 171 项可达。
- 保留下一局嵌入面板的原保存反馈，专门设置弹窗才使用版本核对反馈。完整命令状态、耗时和剩余未验证范围以最终验收报告为准，早期失败不计入通过。
- 真实 CDN 导出曾因测试浏览器没有读取 Node 使用的代理而全部缺图。增加测试端代理与公共 URL 错误诊断，保留“真实封面必须进入 PNG”的断言；普通／大目录重跑通过。完整页面截图先实际滚动展示中的棋盘以触发懒加载，再记录真实加载数量；手机聊天页中隐藏的棋盘不强行滚动。没有修改 Cover 加载器，也没有拿灰色夹具代替对照图片。
- 选牌仍为 180 秒、干扰仍在选牌期间；新时长、独立干扰和 manual-only 互换未启用。没有修改历史轮换、秘密投影、关联板权限、抢夺、撤回、随机互换算法或计分／成就。
