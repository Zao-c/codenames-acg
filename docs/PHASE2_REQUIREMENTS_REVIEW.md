## 4. 已核实的前置问题

### R1：干扰伪装与手选配额、行为可观察性冲突

证据：`shared/view.ts` 的 `captainClaims` 把受害队长收到的干扰 claim 改成 manual；`AnimePlay.tsx` 按 manual 计算 `own.length` 和替换列表；`anime-draft.ts:editDraft` 的撤回和替换仍只接受真实 manual。

本地隔离脚本 `artifacts/handoff-audit.mts` 使用真实 GameService 建立测试组牌，证实：只投一张干扰时受害队长视图手选数为 1，服务端实际为 0；该牌显示 manual，撤回却返回“只能撤回己方普通手选牌”。因此存在确定的配额展示错误和可用于辨认干扰的操作差异。即使统一错误文案，成功/失败和自身操作历史仍会暴露差异；二次确认不能解决此问题。

主规格第 4 节明确允许双方队长看到官方干扰信息；较新报告把“对方队长不知干扰”当作实现目标，两者存在产品语义冲突。建议恢复主规格的**双方队长可见、普通队员/观众不可见**，配额只统计真实手选；这需要确认规则选择，不能以纯 UI 修复之名悄悄修改。若确要隐藏给受害队长，必须另行定义可撤回性、配额及可观察行为的新规则，现有硬规则下不能保证不可辨认。

**解决记录（2026-10-16，`e21aacb`）**：已按主规格恢复——双方队长可见干扰及来源，普通队员/观众只接收静态候选集；手选配额只统计真实手选，原“视图手选数不符、撤回被拒”的冲突随掩码移除消失。正式网站浏览器验收含“双方队长均可见干扰且不占手选配额”断言。

### R2：用户名会话不是账号所有权证明

`index.ts` 的 `/api/users/login` 仅接收 username，`JsonUserStore.login` 根据名字生成有效会话，没有密码/Passkey 等所有权校验。后续 `verifySession` 虽存在，却不能阻止另一个客户端以相同用户名重新取得会话。本轮隔离用户存储已复现“同名再次登录得到另一个有效 token”，没有读取真实账号数据。

因此私密复盘不能只凭 username 或其现有登录 token 授权，社区管理员不能按昵称授予。房间随机 session token 可作为持有者凭证，但须封堵同名重登继承旧成员身份的路径，并建立与昵称分离的稳定主体和离房后的成员凭证。社区云端个人数据/管理入口开放前，另行完成可靠账号所有权认证与旧数据迁移策略；不得自动把旧同名数据认领为新账号资产。

### R3：前队长身份记录不足以直接复用为预测资格

`exposedPlayerIds` 跟踪当前已知 playerId；`joinSpectator` 新昵称可新建 spectatorId。第二批必须增加按 match 保存的稳定主体秘密接触记录，覆盖组牌队长、正式队长、卸任者、调试全知视角及重连/晋升/退出。不能仅检测当前 role 或当前数组里的成员。

建议：房间内参与主体与会话凭证绑定，角色变化不换主体；保留本局退场者记录；客户端不自报主体 ID。仅凭匿名新设备/新账号不能可靠证明现实中是另一个人，不能承诺完全防小号；这个限制应与同一已知主体的严格禁入区分。

### R4：房间锁不是失败回滚事务

`MemoryRoomStore.getRoom` 返回对象引用，`guessCard` 当前直接修改该对象；仅在翻牌前插一行“保存快照”不足以保证异常时一致性。新流程应对当前局聚合状态作副本，完成验证、图谱深拷贝、预测冻结及翻牌计算后，一次提交房间状态。失败不发布半成品，不另起异步 snapshot 回调，也不在确认弹窗出现时提前冻结。

### R5：出站、归档与成员资格有多条路径

`sanitizeRoom` 是 room_state 主裁剪入口，但并非全系统唯一出口：还有 `round_highlight` / `achievement_unlock` / `room_summaries`、错误消息、REST 与公开回放（`index.ts` 直接返回保存的 GameReplay）。必须逐一列入泄密检查。

`ensureReplay` 保存后会晋升候补；私密复盘的本局 ACL 必须在晋升前固定。当前 `draftReview` 随当前局状态变化，不能承担历史私密归档。内存回放重启丢失，默认七天也不等于可跨重启恢复；是否增加私密归档落盘须明确选择。

## 5. 建议采用的边界与待确认项

以下是方案建议，尚非新增已确认需求，完整实施步骤见 [第二批实施计划](PHASE2_IMPLEMENTATION_PLAN.md)。

| 决策 | 推荐方案 | 影响 |
| --- | --- | --- |
| 干扰可见性 | 回到主规格：双方队长可见，普通人不可见 | 可一并解决错计配额和假撤回；若坚持完全伪装，需先调整玩法规则 |
| 实时团队图权限 | 同队未接触秘密的队员可读写；当前队长只读同队图，只能写自己的私人意图；卸任队长不参与实时团队图 | 避免通过协作画图向队员传递阵营秘密；队长不能替队员画“答案” |
| 换队长 | 官方牌桌继承；个人意图不自动交给接任者；旧锁定计划归档保留 | 主规格只规定组牌官方状态继承，未授权私人思路自动移交 |
| 正常结束私密复盘成员 | 当局正式参赛者（包括中途退出但仍能证明身份者）；观众仅自己的预测，分享先限定给该局成员 | “本局成员”是否含纯观众、分享是否允许公网链接仍需确认；先选最小可见范围 |
| 预测评价 | 只按实际翻开且已冻结的牌计算；红/蓝命中即正确，中立/刺客预测计错误；零有效预测显示未参与；终局未翻牌不纳入 | 主规格未规定分母及未翻牌处理，不自行用终局全揭密补算 |
| 保存期限 | 第一阶段私密归档沿用内存与七天 TTL，并清楚提示重启丢失；若要求跨重启查看，增加独立持久化交付项 | 不引入隐含 Redis/多实例改造；社区作品池必须落盘，二者不混为一谈 |
| 社区身份与管理 | 先建立可靠所有权认证，再开放写入/管理；管理员使用独立服务端授权 | 具体登录手段与旧账号迁移需要确认；不临时按昵称白名单给管理权 |
| 玩法范围 | 第二批界面先开放动画词牌；模型引用通用 Card.id，为经典模式复用留边界；揭幕猜番不接入 | 是否同时给经典模式开放关联板尚无明确要求 |

确认前可以继续完善方案、复核证据；不把第二批新功能直接发布到现有玩家。第三批是否还有另一份文档或讨论记录，待用户补充后再形成独立规格。
